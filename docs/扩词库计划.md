# 扩词库：从 16 词 → 2000 词 / 300 词根

## Context

现在词库只有 16 个词、12 个词素（4 前缀 + 4 词根 + 4 后缀），是手写的 `src/domain/data.ts`。玩法（拼词 → 猜义 → 结算 + 配对复习）已经跑通，但 16 个词玩两轮就到底了。

目标：**2000 词 / 300 词根**，覆盖中考 → 四级 → 六级主力词。

关键约束（用户原话）：**「我不懂英文，没法审」**。所以整条链路不能依赖人工校对——质量闸门必须是**规则校验 + 第二个 AI 对抗式复核**，用户只需要知道「丢了几个词、为什么丢」。

核心矛盾：**没有任何数据集有「画面选项」和「怎么记」**。ECDICT 有中文释义，Wiktionary 有词源，Tatoeba 有例句，MorphyNet 有切分——但 `literalMeaningCn`（字面画面）、`metaphorOptions`（三选一）、`mnemonicNote`（怎么记）这三样必须生成。所以这不是「找个完整词库下载」的问题，是**搭一条数据管线**。

### 三个许可决定（重要）

1. **Wiktionary 只离线用作「切分是否真实」的证据，不进产物。** 出厂的 `sourceNote` 由 LLM 基于词素义重新写成「构词逻辑」句，不是抄词源。这样产物保持 MIT 兼容。否则整个仓库要转 CC BY-SA 4.0——**单向门，不能反悔**。
2. **两个中文词根表不抄 `meaningZh` 原文。** 只用它们推导**候选词根 id 列表**（事实性信息），所有出厂的 `meaningCn` / `etymology` 全部重写。
3. 生成 `CREDITS.md`（Tatoeba 例句 id、ECDICT 版本 hash），加 `scripts/gates/license-manifest.json` 把每个字段映射到来源和许可，闸门检查「share-alike 字段不得出现在标记 MIT 的文件里」。

### 许可结论（对早先的更正）

**早先这里写的是「两个中文词根表找不到 LICENSE」——那是不对的，两家都有 LICENSE 文件。**
更正后的事实：

| 仓库 | 仓库自己标的 | 实际状况 |
|---|---|---|
| jesselau76/cigen | MIT | `data/` 由 `scripts/extract_pdf_data.py` 从新东方 PDF 抽取 |
| shiweihappy/english-word-root | Apache-2.0 | `scripts/extract_xdf.py` 从新东方 PDF 抽取 |

**仓库作者无权给上游内容再授权。** 所以 MIT / Apache-2.0 这两个标只在「仓库自己写的那部分代码」上成立，
盖不住 `data/` 里的释义文本。**禁止逐字复制的结论不变，但理由变了**——
不是「没有许可证所以不能抄」，是「有许可证但许可范围不覆盖内容」。

**唯一许可干净、结构完整的来源是 ECDICT 自带的 `wordroot.txt`**（611 条，MIT，
英文义项 + 拉丁/希腊来源 + 例词）。它是权威来源，中文释义由 LLM 基于它的英文字段重写。

## 运行时数据放哪

按现文件实测 **966 B/词** 的 TS 源码，压缩成 minified JSON 约 **800 B/词**（中文 3 字节/字，压不掉）：

- 2000 词 ≈ **1.6 MB 原始 / 550 KB gzip**
- 300 词素 ≈ 75 KB / 25 KB gzip
- 只留索引层（`id word phonetic partOfSpeech modernMeaningCn difficulty parts`）≈ 610 KB / **180 KB gzip**

各页面真实需求：

| 页面 | 需要什么 |
|---|---|
| 今天 | **零个词**——只用 `completedWordIds.length` 和 `getReviewQueue` |
| 词根地图 | **全部 300 个词素**，零个词 |
| 拼单词 | 1 个词（全字段）+ 家族词 |
| 复习 | ≤ 6 个词，只渲染 `word` + `modernMeaningCn` |
| `pickNextWord` | **全部 2000 个**，但只用 `{id, parts}` |

**决定：拆类型，不拆同步加载。** `Word` 保持同步（不把 async 灌进渲染树、不改纯函数测试风格），但拆成两层 + 懒加载详情：

```ts
// src/domain/types.ts
export interface WordCore   { id; word; phonetic; partOfSpeech; modernMeaningCn; difficulty; parts: WordPart[] }
export interface WordDetail { literalMeaningCn; metaphorMeaningCn; metaphorOptions: string[]; exampleEn; exampleCn;
                              distractors; sourceNote; mnemonicNote }
export type Word = WordCore & WordDetail      // 对外类型不变
```

- **立即加载**：`morphemes.json` + 生成的 `WordCore[]` 索引（180 KB gzip）
- **懒加载**：`WordDetail` 切成 ~24 片（每片 ~85 词），`chooseWord()` 打开某个词时 `import('./details/shard-07.json')`，配 `Map<string, WordDetail>` 缓存
- **接缝**：`logic.ts` 至今不 import data（`getMorpheme` / `allWords` 是注入参数），保持住。`pickNextWord`/`getReviewBoard` 只读 `id` 和 `parts`，参数类型改成 `readonly WordCore[]`，领域层永远不知道分层存在

**Stage 1（≤400 词）先不拆**，直接一个生成的 `words.ts`。分层是 Stage 3 的事，但 `WordCore`/`WordDetail` 类型拆分放 Stage 0 落地，后面切换就是机械操作。

产物用 **JSON 不用 TS 字面量**：生成的代码不能含代码、能 diff、`tsconfig.app.json` 已有 `"resolveJsonModule": true`。`src/domain/data.ts` 保持为薄包装层，这样 `App.tsx:2`、`logic.test.ts:2`、`persistence.ts:1`、`content.test.ts:2`、`scripts/validate-content.mjs:1` 的 import 路径全不用改。生成的 JSON 放 `src/domain/content/`。

### LLM 生成契约（`30-llm-prose.mjs`）

**输入是 JSON 对象，不是散文。** 每词：

```json
{ "word": "circumspect", "phonetic": "/ˈsɜːrkəmspekt/", "partOfSpeech": "adj.",
  "modernMeaningCn": "谨慎的；周详的",
  "parts": [{"morphemeId":"circum","surface":"circum","meaningCn":"周围"},
            {"morphemeId":"spec","surface":"spect","meaningCn":"看"}],
  "etymologyFromWiktionary": "From Latin circumspicere …",
  "exampleEn": "She was circumspect about making promises.", "exampleCn": "她对做出承诺一事十分谨慎。" }
```

系统提示里的硬约束：

1. **`parts` 是冻结的、权威的**。不许增删改序、不许重新切分、不许提到列表外的词素。
2. `literalMeaningCn`：只用给定的 `meaningCn` 按顺序组成的画面句，≤12 汉字，无拉丁字母，**不得**是 `modernMeaningCn` 的复述。
3. `metaphorMeaningCn`：≤20 汉字，从 `literalMeaningCn` 推出来，但不得与之逐字相同。
4. `metaphorOptions`：恰好 3 个，`[0]` 正确。`[1]` 必须复用**本词自己某个词素** + 从全局义项池里取的**错误**中文释义；`[2]` 是合理的无关画面。各 ≤20 汉字，无拉丁字母。
5. `mnemonicNote` ≤40 汉字且必须含字面画面；`sourceNote` ≤60 字。
6. **`sourceNote` 只在 `etymologyFromWiktionary` 非空时才可用「来自/源自/拉丁语」。** 否则必须写成「构词逻辑」。（可机器检查）
7. 逃生舱：`{"reject": true, "reason": "…"}`——当 ECDICT 释义与词素义矛盾时。

**强制约束**：JSON schema（`additionalProperties:false`、`required` 全 7 字段、`metaphorOptions` `minItems:3,maxItems:3`、每个字符串有 `maxLength`）。每批 10 词（失败只损失 10 个），逐词落盘以便断点续跑，temperature ≈ 0。

**结构上的关键点：模型永远不会被要求产出 `id`、`parts`、`difficulty`、`familyWordIds`、`distractors`。** 切分没法被幻觉，因为模型根本没机会写切分。只有文案会错，而文案正是第二道 AI 复核管的。

**`distractors` 在 `assemble.mjs` 里算，不生成**：`form` = 与本词某段共享 ≥3 字符前缀但 id 不同的词素；`meaning` = `meaningCn` 落在同一个中文语义簇但 id 不同的词素；`random` = 定种子随机取。取完再对 `parts[].surface` 过滤。种子固定保证产物可复现。

## 质量闸门（全自动，不依赖人读英文）

### A. 规则闸门（重写 `scripts/validate-content.mjs`）

用 `node` 裸跑，读 **JSON 产物**（`readFileSync` + `JSON.parse`），这样能在 TypeScript 编译前校验。共用规则放 `src/domain/contentRules.ts`，测试也 import 同一份实现。

> 注意：Node 22.18+ 默认剥离类型，`node scripts/validate-content.mjs` 现在就能 import `.ts`。但**只支持可擦除语法**——不能有 `enum`、`namespace`、参数属性，也不能有无扩展名的 `.ts` import。共享规则模块必须守这条。

**逐词**

1. 16 个字段齐全非空；`phonetic` 匹配 `/^\/.+\/$/`；`partOfSpeech` 在闭集内
2. `difficulty ∈ {1,3,5}`（闭集，否则 `logic.ts:191` 的 `DIFFICULTY_MULTIPLIER[difficulty]` 得 NaN）
3. `parts.length ≥ 1`；`parts[i].position === i`（沿用 `logic.test.ts:326`）
4. 每个 `parts[].morphemeId` 都已建模（沿用）
5. **【最强反幻觉闸门】** `parts.map(p=>p.surface).join('').toLowerCase() === word.toLowerCase()`，外加 `scripts/gates/residue-allowlist.json` 里显式声明的残留。注意 `porter`（`data.ts:107`）只有 `parts=[port]`，拼出来是 `port` 不是 `porter`——`-er` 未建模。规则写成 `word === concat + residue`，残留必须在白名单里带书面理由
6. 每个 `surface` ∈ 该词素的 `allomorphs` ∪ {`displayText` 去连字符} ∪ 显式白名单。**这条会在现有数据上失败**：`visibility`（`data.ts:137`）用 `ibil` 表示 `able`，而 `able.allomorphs = ['able','ible']`
7. `exampleEn` 作为整词包含 `word`，允许 ECDICT `exchange` 里的变位（`d:/p:/3:/i:`）和 `-e → -ing/-ed` 脱落
8. `exampleCn` 含 `[\u4e00-\u9fff]` 且**不含** `[A-Za-z]`
9. `exampleEn` 词数 4–20
10. `metaphorOptions.length === 3` 且互不相同（沿用 `content.test.ts:19`）
11. **【新】** `metaphorOptions[0]` 与 `[1]`/`[2]` 的字符二元组 Jaccard 相似度 **< 0.5**——抓「干扰项是答案的复述」，字符串相等抓不到
12. **【新】** `[1]`、`[2]` 各自至少含 1 个全局义项池里、且**不在**本词正确义项序列里的中文义——保证错项是「有具体理由地错」
13. `literalMeaningCn` / `metaphorMeaningCn` / 所有 `metaphorOptions`：无拉丁字母；`metaphorMeaningCn !== literalMeaningCn`
14. `mnemonicNote` 和 `sourceNote` 不得逐字包含 `modernMeaningCn`，且两者不得相等（`logic.test.ts:56` 的自动化版本）
15. `distractors.length ∈ [3,5]`；`type` 合法；**每个干扰项用 `normalizeMorphemeKey` 归一后必须解析到真实 `morpheme.id`**，或在 `gates/unmodeled-distractor-allowlist.json` 里。这条把 `App.tsx:227` 那个「合成假词素」的兜底路径对新数据彻底关掉
16. `familyWordIds`：全部存在（沿用）；不自引用；每个成员至少共享 1 个 `morphemeId`；长度 2–8
17. `id === word`；id 与 word 全局唯一
18. **【新】** 每个词至少 1 个 `type === 'root'` 的 part。否则 `getRootId`（`logic.ts:125`）会退回 `parts[0]`（一个前缀），`applyCompletedCase`（`logic.ts:319`）找不到进度记录，**静默给 0 经验**
19. provenance 边车覆盖：ECDICT 100%、Tatoeba ≥95%、LLM 100% 记录模型名

**逐词素**

20. id 唯一 `[a-z]+`；type/color 一致（蓝/橙/绿）；`level ∈ 1..5`；`meaningCn` 1–8 汉字；`displayText` 全局唯一
21. `etymology` 只在 provenance 标了 Wiktionary 时才能含「拉丁语/希腊语」
22. 每个 `allomorphs[]` 至少被 1 个词的 `parts[].surface` 用到——不留死变体
23. 每个词根 **≥3 个词**，且 **≥1 个 difficulty-1、≥1 个 difficulty-5**

**全局**

24. `world.morphemeIds` 全部已建模；world 覆盖所有词根
25. `createInitialProgress().length === rootMorphemes.length`
26. `difficulty` 值域 ⊆ {1,3,5}；world id ⊆ 生成的 `WorldId` 联合类型
27. `quarantine/*.major.json` 为空，或每条都在 `gates/quarantine-approvals.json` 里

### B. 第二个 AI 复核（`60-llm-review-content.mjs`）

- 跑在**组装后的产物**上，不是生成器输出上——这样才能抓到切分器和组装器的 bug
- **分批**：8 词/请求，2000/8 = 250 个请求，并发 4–6，指数退避。结果缓存在 `.work/review-cache/<sha256(batch+promptVersion)>.json`，重跑免费且幂等
- **给复核者什么**：冻结的 `parts` + 词素义、`word`、`phonetic`、`partOfSpeech`、`modernMeaningCn`、ECDICT 原始 `translation`、词源片段、待审文案、Tatoeba 例句对——**不给生成器的推理过程**，且用**不同的模型**，对抗式提示（「你的任务是找出缺陷，默认倾向于报告」）
- **强制 schema**，逐词：

```json
{ "id": "circumspect",
  "checks": { "splitMatchesWord": true, "splitMatchesEtymology": true,
    "literalComposedFromGlosses": true, "metaphorExtendsLiteral": true,
    "optionsThreeDistinct": true, "optionAIsCorrectAnswer": true,
    "optionBWrongForStatedReason": true, "optionCWrongForStatedReason": true,
    "exampleEnContainsWord": true, "exampleCnTranslatesExampleEn": true,
    "sourceNoteConsistentWithEtymology": true, "mnemonicFreeOfAnswerLeak": true,
    "noInventedMorpheme": true },
  "severity": "ok | minor | major",
  "issues": [{ "field": "metaphorOptions[1]", "problem": "…", "suggestedFix": "…" }] }
```

- **路由**：`major` → 写 `quarantine/<date>/<id>.json`，组装器**带排除清单重跑**，该词永不出货。`minor` → 出货，计入报告。`ok` → 出货。仅对标记词做第二轮修复请求，修完的文本**必须重新过 A 类规则闸门**才能写回
- **规则与复核冲突**：规则赢（确定性），但记进 `report.md`，这样跨轮次的模型漂移可见
- **批准文件不是校对闸门**——用户读不了英文，它只是**记录「有 N 个词被有意识地丢弃」**。产物就是变小了
- **漂移探测器**：用完全相同输入对 2% 随机样本重跑生成器，测不一致率。超过 5% 判定提示词不稳定，**阻断发布**。这是无人工读者时唯一能发现 LLM 漂移的机制

### Stage 0 —— 在 16 词上做重构，零内容变化

### Stage 1 —— 管线打通：60 词 / 20 词根，人工挑词

跑 00→70 全链路。

**验收**：所有闸门绿；隔离 ≤2 个词且有书面理由；记录词条 chunk 的 gzip 体积；20 个词根在地图页渲染不破版。

### Stage 2 —— 300 词 / 60 词根，全自动

第一个数据量足以让聚合闸门（每词根难度分布、隔离率）有意义的阶段。

**验收**：隔离率 < 5%；闸门零错误；量出词根覆盖数。

**每个阶段结束后**：`rm -rf scripts/.work/derived && npm run content:all`。只能增量跑的管线不算可复现，而可复现是用户读不了英文时**唯一的替代品**。

## 风险

1. **许可污染（最难的一条）。** Wiktionary / MorphyNet 是 share-alike，衍生的词源文本会让产物继承 CC BY-SA。已定 Option A：这两份**只离线当证据**（放在 gitignore 的 `scripts/.work/`），出货文本全部重写，产物保持 MIT 兼容。本仓库的 `LICENSE`（MIT）已落地。两个中文词根表虽然各自贴了 MIT / Apache-2.0，但内容是从新东方 PDF 抽的、许可盖不住——**不要逐字复制它们的 `meaningZh`**，只用候选 id 列表。商用的话词根 id 列表需要律师看一眼。
2. **LLM 幻觉切分。** 结构上已排除（模型从不需要产出 `parts`）。兜底是确定性的 `concat(surfaces) === word` 闸门，失败**丢弃、绝不修复**。残余风险是「拼得起来但切错了」（`re+port` vs `rep+ort`），靠 `surface ∈ allomorphs` 和复核者的 `splitMatchesEtymology` 抓。注意：如 §A.6 所述，allomorph 规则需要白名单，因为现有 `ibil`/`able` 已经违规。
3. **中文语义漂移。** ECDICT 给的是多义词典释义，词根表给的是词素义。失效模式：`literalMeaningCn` 拼出来的画面不是这个词的意思，或 `metaphorMeaningCn` 与 `modernMeaningCn` 无关。缓解：(a) `modernMeaningCn` 钉死为 ECDICT 该词性第一义项；(b) 提示里先给 `literalMeaningCn` 再给 `metaphorMeaningCn`，且复核者必须勾 `metaphorExtendsLiteral`；(c) **确定性漂移信号**——`metaphorMeaningCn` 与 `modernMeaningCn` 的二元组重合度 < 0.1 判为无关 → 隔离；(d) 两个词根共享 `meaningCn` 时告警（`spec`/`vid` 现在已经都是「看」）。
4. **300 词根 × 3 档难度需要每个词根都有 difficulty-1 和 difficulty-5 的词。** 这是最可能击穿 300 目标的风险。`logic.ts:191-192` 意味着简单词涨 1.5×、难词涨 0.5×，`logic.test.ts:104-116` 断言两个方向都存在。只有 difficulty-3 的词根不会让测试挂，但会压平奖励曲线；**一个 difficulty-1 都没有**的词根则永远不会触发 `logic.test.ts:263` 的每词 18% 涨幅。`20-select-words.mjs` 必须对每个词根瞄准两档；CET 词表供不上时（`loqu` 这类生僻词根很可能会），规则应当**丢掉该词根**，而不是改成「按词根相对难度分档」（那会破坏全局难度语义和权重测试）。**不实际跑一遍选词就无法估计 300 个里能活下来多少——这是头号未知数，在 Stage 2 量，不在 2000 词时量。**
5. **其他。** Tatoeba 对 CET 词覆盖会有缺口——允许 LLM 兜底写 `exampleEn`/`exampleCn`，复核者对这些要查得更严。Node 类型剥离意味着共享 `src/domain/*.ts` 里一个 `enum` 会静默搞坏 `validate:content`。`logic.ts:214` 的 `testedWordIds` 每词根无界增长（今天被家族大小压住，但要测体积）。`main.tsx` 没有 error boundary，Stage 3 的懒加载分片 404 会白屏。
