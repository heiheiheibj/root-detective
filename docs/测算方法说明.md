## 1. 通用约定（所有计算共用）

```
norm(s) = String(s).toLowerCase().replace(/[^a-z]/g, '')
```

**所有词、词素、id 一律先 norm 再比较**。这一步做错会导致两边数字对不上（例如 `self-` 与 `self`、
`-tion` 与 `tion` 必须视为同一个东西）。

**ECDICT 难度规则（6.4）**，输入是某词的 `tag` 数组、`collins`、`bnc`：

```
d1  ←  tag 含 'zk' 或 'gk'，或 collins === 5，或 (0 < bnc < 3000)
d5  ←  (tag 含 'cet6' 或 'toefl') 且 (bnc > 10000 或 bnc === 0)
d3  ←  其余
```

**考试词判定（6.2）**：

```
passTag  ← tag 含 ['zk','gk','cet4','cet6'] 之一
passCom  ← collins > 0 或 oxford > 0 或 (0 < bnc < 20000) 或 (0 < frq < 20000)
pass62   ← passTag 且 passCom
```

**保送（forceInclude，Stage 2 实践）**：`d5` 且 tag 含 `toefl`/`ielts`/`gre`/`cet6` 之一 —— 允许在 6.2 不达标时收录。

## 2. 计算 A：考试词集合（基准分母）

**输入**：`ecdict.csv`

**格式**：CSV，**必须用正规 CSV 解析**（字段可被双引号包裹，内含逗号与 `""` 转义；直接 `split(',')` 会错列）。
列序（0 起）：

```
0 word   1 phonetic   2 definition   3 translation   4 pos
5 collins   6 oxford   7 tag   8 bnc   9 frq   10 exchange   11 detail   12 audio
```

`tag` 是空格分隔的小写标签串。

**定义**：`word = norm(f[0])` 非空，且 `tag` 含 `zk`/`gk`/`cet4`/`cet6` 任一 → 考试词。
同一 norm 词只计一次。

## 3. 计算 B：kaikki 权威词素提取（核心）

**输入**：`kaikki-English.jsonl`（3.24 GB，1,492,836 行，每行一个 JSON 词条）

**目的**：拿 Wiktionary 编辑手工标注的「表面拆分」，得到 词 → 词素序列。

### 3.1 遍历与过滤

逐行流式读取，按顺序计数；对每行：

1. 若行内**不含子串** `"etymology_templates"` → 跳过（纯性能优化，不改变结果）
2. `JSON.parse`；解析失败 → 跳过
3. `obj.lang_code !== 'en'` → 跳过
4. `word = norm(obj.word)`，为空 → 跳过

### 3.2 模板优先级（取第一个命中的）

```
surf → prefix → pre → suffix → suf → confix → affix → af → compound/affix → compound → com
```

> ⚠️ **这一条是最大的坑**：Wiktionary 大量使用缩写别名。
> 只认 `prefix`/`suffix`/`affix`/`surf` 会漏掉 `af`（affix）、`suf`（suffix）、`pre`（prefix）、`com`（compound）——
> 覆盖率会从 41.3% 掉到 18.9%。

### 3.3 从模板取词素

取该模板 `args` 中**所有纯数字键**（`"2"`, `"3"`, …）的值，**跳过 `"1"`（语言码）**，
按数字升序排列，逐个 `norm()`，丢弃空串。

命名参数（`t`/`alt`/`pos`/`id`/`tr`/`gloss`…）都不匹配 `^\d+$`，天然被排除。

### 3.4 模板拿不到时的文本解析

若 3.3 得到的词素**少于 2 个**，则解析 `obj.etymology_text`，按顺序试以下正则，**第一个匹配且片段含 `+` 的胜出**：

```
1) /equivalent to ([^.;]+)/i
2) /surface analysis,?\s*([^.;]+)/i
3) /^From ([^.;]*\+[^.;]*)/i
4) /from ([^.;]*\+[^.;]*?)(?:[.;]|$)/i
```

拿到片段后：

```
pieces = 片段按 '+' 分割
每段：删掉括号内容（/\([^)]*\)/g → 空格）→ norm()
保留：长度 2..20 且 /^[a-z]+$/
若最终 ≥2 个 → 采用，来源标记为 'text'
```

> 例：`"equivalent to king + -dom"` → `['king','dom']`；`"From tele- + vision"` → `['tele','vision']`；
> `"surface analysis, port ("to carry") + -able"` → `['port','able']`

### 3.5 记录

- 词素 < 2 个 → 丢弃
- **每个词只记第一条成功拆分**（`splits` 以 word 为键，先到先得；同一词可能有 noun/verb/adj 多个条目，按文件顺序取第一个成功的）
- 词素 → 词集合：`morphemeWords[morpheme].add(word)`（**用 Set 去重**）

## 4. 计算 C：考试词覆盖率（决定目标）

**输入**：计算 A 的考试词集合 + 计算 B 的 `splits` 映射

### 4.1 覆盖判定

```
covered   = { w ∈ 考试词 : splits[w] 存在 且 splits[w].parts.length ≥ 2 }
uncovered = 其余
```

（因为 B 只收录 ≥2 词素的词，所以等价于「w 在 splits 里」。）

### 4.2 词素统计

对每个 covered 词，遍历其 `parts`：

```
morphemeWords[part].add(word)          // 用 Set
位置计数（用于判前缀/词根/后缀）：
  i === 0            → head += 1
  i === parts.length-1 → tail += 1
  其余                → mid  += 1
```

### 4.3 累计覆盖量

对阈值 k ∈ {3, 5, 10, 20}：

```
hit = { 词素 m : |morphemeWords[m]| ≥ k }
wordsCovered = ∪ morphemeWords[m]   (m ∈ hit)     // 并集，按词去重
输出 |hit| 与 |wordsCovered|
```

## 5. 计算 D：可切分口径天花板（否决旧目标的依据）

> 这个计算是为了回答「沿用 Stage 2 那套小词根表，最多能扩到多少词根」。
> 结论 155 是被否决的旧目标依据；如果对方算出的也是 ~155，说明两条路线独立得到了同一结论。

**输入**：`roots.candidates.json`（406 条候选词根，`type === 'root'` 的参与计算）、
`cigen-roots_affixes.json`、`morphynet-eng-derivational.tsv`、`wordroot.txt`（通过候选的 `examples` 字段）、`ecdict.csv`

### 5.1 每个候选的表面形式

```
surfaces = { norm(id) } ∪ { norm(a) : a ∈ allomorphs }，丢弃长度 < 3 的
```

### 5.2 家族词收集（三个来源）

| 来源 | 取法 |
|---|---|
| `cigen` | `components[].morpheme` 归一化后**全等**于某个 surface → 该 `word` |
| `wordroot` 例词 | 候选的 `examples[]` 中，**字面包含**某个 surface 的 |
| `morphynet` | TSV 第 5 列归一化全等于 surface → 取第 1、2 列的 word，且**字面包含**该 surface |

**「字面包含」规则**：

```
surface 长度 ≥ 4 → word.includes(surface)
surface 长度 = 3 → word.startsWith(surface) 或 word.endsWith(surface)
```

**Morphynet 额外要求「词根不在词尾」**：

```
若 word.endsWith(surface) 且 word.length > surface.length + 1  →  剔除
```

> 这条只对 morphynet 用。复合词误判全来自它（`king|dom`、`police|man`）。
> cigen/例词不能用这条，否则会误杀 `attend`/`extend`/`intend`（前缀+词根结构）。

### 5.3 难度与合格判定

对家族词逐个查 ECDICT：`pass62(e)` 或（允许保送时 `canForce(e)`）→ 计入可用词。
然后 A23：

```
合格 ← 可用词 ≥ 3  且  d1 ≥ 1  且  d5 ≥ 1
```

（「放宽 d5」口径即去掉最后一条。）

### 5.4 已用词根判定（影响「未用」计数）

```
usedSurfaces = ∪ { norm(m.id), norm(m.allomorphs) : m 是 stage3-content.json 与 legacy-morphemes.json 里 type==='root' 的词素 }
候选若任一 surface ∈ usedSurfaces → 视为已用
```

> 只看 `id` 会把 `spect` 当新词根（它是已用 `spec` 的变体），从而高估天花板。

### 5.5 预期结果

| 口径 | 合格词素 | 其中未用 | 天花板（60 + 未用） |
|---|---|---|---|
| X1 严格 6.2 + 完整 A23 | 49 | 27 | 87 |
| **X2 允许保送 + 完整 A23** | **138** | **95** | **155** |
| X3 允许保送 + 放宽 d5 | 164 | 116 | 176 |

未用候选的失败原因：**词不足 3 个 209 / 缺 d1 28 / 缺 d5 21**。

## 6. 已知陷阱（数字对不上先查这里）

1. **CSV 必须正规解析** —— ECDICT 有引号包裹、内含逗号的字段，`split(',')` 会错列
2. **模板别名** —— 漏 `af`/`suf`/`pre`/`com` → 词素少一半，覆盖率 41.3% → 18.9%
3. **不解析词源文本** —— 漏 `"equivalent to X + Y"` 这类句式 → 同样大幅低估
4. **norm 不统一** —— 一边 norm 一边不 norm，匹配率骤降
5. **模板 `"1"` 键** —— 是语言码，必须跳过
6. **每个词只记一条拆分**（不是合并所有模板）
7. **词素计数用 Set 去重**（同一词重复出现同一词素只算一次）
8. **`bnc === 0` 的含义** —— 视为「无排名/冷门」，在 d5 判定里算达标
9. **`lang_code` 字段** —— kaikki 的 JSON 里语言码字段名是 `lang_code`，不是 `lang`
10. **流式读取** —— 3.2 GB 文件不要一次性 `readFileSync`

## 7. 无法自动验证的部分（主观判断，需人工）

以下结论**不来自脚本**，是我基于抽检的人工判断，交叉验证时请单独讨论：

1. **语义可教性** —— 脚本只量「能不能切」，量不出「讲不讲得通」。
   例：`man`(hand) 的家族混入 `permanent`（词源 manere=停留）；`dom` 既是「房子」词根又是 `-dom` 后缀。
   抽检 6 个候选的结论：约 80% 判定可信，剩 20% 需人工剔除。
2. **词素类型归类** —— `head/mid/tail` 位置统计只能**提示**前缀/词根/后缀，最终归类要人工。
3. **155 这个天花板**包含上述人工折扣，**纯脚本输出是 X2 的 138/95**。
4. **目标该定多少** —— 是产品决策，不是计算结论。
